01

ONE SMALL LOOP

第一份完整代码

先安装果农的选择回调，再在每次判断时读取当前单池法力。完整示例独立于排名程序，不修改默认策略。

采集与火箭 JavaScript
var gatheringElement = "fire";
var attackSpell = "fire-arrow";
var attackCost = 3;

hero.chooseItem = function (collector) {
  return gatheringElement;
};

while (true) {
  var availableMana = hero.getTotalMana(gatheringElement);
  if (availableMana >= attackCost && hero.canCast(attackSpell)) {
    hero.cast(attackSpell);
  }
}
不依赖 cast 返回值；无打印、隐藏 API 或自动对局。
下载完整 JS 示例 ↓仅供教师后续平台验证，不在网页执行。
代码的目的与边界
代码为什么这样写不能据此保证
chooseItem返回采集元素，不读取额外果农字段固定收入率或最优采集比例
getTotalMana("fire")重新读取火池，不使用三池合计旧读数仍能用于这一次判断
attackCost = 3门槛来自简介的箭费用列3 是伤害或本示例的实测费用
&& canCast费用不够时短路，够了再检查可用性false 能指出唯一原因或冷却时间
cast两道条件满足后发出调用已经命中、掉血或获胜
想一想

只把采集改成 water，攻击却仍然用 fire-arrow，会发生什么？采集、查询池、法术元素和费用必须一起核对。

教师提示与下一步

单元素采集只是最小讲解选择，不是最优比例。法力不足时，&& 不再执行 canCast；条件满足时的调用也不等于实际命中。

一名初始果农可能效率很低，但本课不同时改多个因素。第三课再比较扩张收益与生成阻塞，不能直接用这份入门代码承诺实战强度。
