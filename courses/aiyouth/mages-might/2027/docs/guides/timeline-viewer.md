# 本地手动快照查看

这是独立的只读展示原型，不是新课程、比赛回放或证据验收器。页面不登录、不连接比赛，不注入或执行策略，不读取其他标签页，不上传或自动保存文件。

## 现在能做什么

1. 打开 `tools/timeline-viewer.html`，或从教学首页的「本地工具」进入。
2. 没有文件时，先点「虚构教学示例」；它演示缺失帧、unknown 和读取错误，不是实战数据。
3. 手动选择已有只读采集器下载的 JSON。每次选择仅替换当前标签页内存中的展示；失败时保留上一份，并明确提示本次未载入。
4. 选择实体、输入帧序号或移动滑块，逐项查看原始字段与该帧诊断。
5. 点「清空展示」移除当前展示数据；不会改原文件，也不会撤销已发生的比赛行为。

本轮没有安装油猴或执行真实比赛。后续真实联调必须另行授权；若重进官方对战页，需要先手动点击右下角「开始」，再自行写程序、运行；本查看页不负责这些动作。

## 文件格式与边界

采集格式来自 `build/userscript.mjs` 与 `adapters/codecombat/observer.mjs`：

- 外层 `schemaVersion=1`、`captureType=manual-snapshot`、`adjudicated=false`，带可解析的 `capturedAt`。
- `raw` 为 `ok=true`、`schemaVersion=1`、`source=world.frames` 的只读帧快照，包含 `frameCount/frames/entities/errors`；不含 `winner/endedBy`。
- 只展示 `health/fire/water/earth/mana/pos/exists`。额外源码、凭据或任意其他字段不进入展示模型；不能由此保证上传前的原文件不含敏感信息。
- 只接收手动快照，不接受 T002-12 的命令行结果 dump、参赛源码或任意结果报告。
- 每次最多 8 MiB UTF-8 文本、10000 帧、500 个实体、20000 条读取诊断；实体 ID 为非空且唯一的短文本（最多250字符），诊断原因最多80字符。

格式检查只为安全展示；没有签名、runId 身份绑定、末帧完整性核对或平台终局闸门。即便成功打开，仍不能确认文件来源、版本、运行身份、数据真实性或完整性。本模块不接入 facts、原始证据库或正式胜负判定链。

## 如何阅读

- `unknown` 不等于 0。帧或实体缺失不能证明死亡或不存在；有明确 `exists=false` 时只展示该原始值。
- 读取诊断会将对应值保持 unknown，即使文件同处也写了数值；不删除失败记录。
- `fire/water/earth` 是各池数量；`mana` 可能是元素字符串，不能统一当数量。
- 游戏时间按文件的帧率计算；帧率缺失或派生时间不可表示时保持 unknown，不硬套常数，也不换算真实耗时。
- 前20帧按现有平台适配器约定标为预热、只展示。非预热不意味着可信；本查看页始终不判终局、胜负或置信度。

先回到第五课写问题、假设、单一改动和下一次对照，再讨论这些数值能支持什么。不要把“最后一帧能读到血量”当成已确认整局结束。
