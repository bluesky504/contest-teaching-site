# 第三课：扩张与阻塞取舍

**状态：教学示例草稿，待当前平台实跑与独立复验。** 沿用第二课，只增加一次生成调用；不声称这是一种更强的策略，不修改排名代码或默认配置。

## 本课问题

更多果农可能带来更多后续收入，但英雄生成调用没有返回时，后续攻击和防御代码不能先执行。应该问的不是「果农越多越好」，而是「付出这次行动窗口后，剩余时间与战场风险是否容许扩张」。

**不要混淆两件事**：英雄后续调用被阻塞，不等于原有果农停止采集。本课不计算它们的收入，也不把它们当成全部停工。

## 完整代码：只增加一次尝试

源码：`examples/teaching/mages-might/03-expansion-and-blocking.js`。与页面及下面的代码逐字一致。无限主循环只能交给合适的平台或有界测试，不能直接当普通 Node 或网页脚本运行。

```javascript
var gatheringElement = "fire";
var attackSpell = "fire-arrow";
var attackCost = 3;

hero.chooseItem = function (collector) {
  return gatheringElement;
};

hero.spawnCollector();

while (true) {
  var availableMana = hero.getTotalMana(gatheringElement);
  if (availableMana >= attackCost && hero.canCast(attackSpell)) {
    hero.cast(attackSpell);
  }
}
```

1. **先安装回调**：在生成与后续采集请求之前，给出有效元素字符串。
2. **只尝试一次**：`spawnCollector` 在主循环外，不是每次循环再造一个。
3. **返回后再进入攻击循环**：此例没有插入并发、防御或未验证的 wait API。
4. **不依赖返回值**：历史 `spawnCollector` 调用返回 undefined，不能据此判断出生成功。实际新增身份、生命与调用起止仍须读取原始证据；此例不承担完整出生确认。

## 小模型：只看新增采集窗口

假设本次英雄阻塞为 B 秒，可用于讨论的剩余窗口为 T 秒，新增果农从返回后立即以固定 r 入账：

- 新增采集窗口 = `max(0, T - B)`。
- 额外法力假设量 = `窗口 × r`。
- 若已知示意威胁将在 D 秒后到达，余量 = `D - B`；非正时，威胁不晚于返回。

页面默认 **B=4、T=20、r=0.5、D=3**，得到窗口16秒、额外法力8、威胁早于返回1秒。4秒与0.5是教学假设，不是某个真实果农的耗时或收入率。改变阻塞与剩余时间，观察「有收入」仍可能伴随无法及时响应的风险。

模型故意忽略首趟往返、排队、果实数值、果农死亡、攻击消耗和原有果农收入。正收入不能证明回本或值得生成；正反应余量不代表能防住，还缺施法耗时、采样延迟与实际飞弹数据。来袭时间未知时显示「无法评估」，不伪造安全结论。

## 控制变量练习

- 对照第二课与本课：只改变一次生成调用，采集元素与火箭逻辑不变。
- 若将来实跑，分别记录新增身份、生成起止、首次后续施法、实际法力曲线与双方血量；失败或报错不记成可信结果。
- 分别考虑开局平静、飞弹即将命中、对局快结束三种场景。不要把一次获胜解释成更多果农总是更好。
- 英雄生成时原有果农是否继续采集？这是另一个观测问题，不能用调用顺序的 fixture 来替代实测。

教师提示：这份示例固定开局尝试一次，没有读取场面风险，不是动态扩张算法；先理解取舍，再在后续课设计攻防预算。
