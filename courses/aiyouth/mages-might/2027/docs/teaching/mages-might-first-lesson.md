# 第一课：从比赛规则找到可用接口

**状态：教学草稿。** 面向已经接触变量、条件和函数的学生；不是可直接参赛的完整程序，未作为一份新策略在当前比赛页实跑或公开发布。

## 学完能做什么

- 画出「果农采集 → 三池法力 → 施法消耗 → 战场变化 → 再观察」的循环。
- 找到读取果农、单元素法力、来袭飞弹的 JS 入口。
- 分清规则说明、观测证据和自己提出的策略假设，避免把猜测写成结论。

## 先读规则，不急着写最强程序

在比赛页先打开「提示 → 简介」，看清表格每一列。教师已有全文阅读记录在 `docs/guides/battle-intro-reading.md`，其中保留了来源与版本。

| 看见的内容 | 应该怎样理解 | 不应直接推出什么 |
| --- | --- | --- |
| 魔法 mana | fire、water、earth 等元素类型 | 它不是法力点数 |
| 费用 | 本方消耗的对应元素法力 | 不是对方实际掉血量 |
| 法力／威力 | 攻击或特殊效果的说明值 | 有盾时英雄仍一定掉同样的血 |
| 持续时间 | 界面文档中的时间说明 | 必然等于飞行时间、冷却或盾的自然寿命 |
| 火克土、水克火、土克水 | 界面说明的元素相克关系 | 不用区分盾和攻击方向，或所有旧版本都已实测 |

**讨论**：为什么刚好学会一个可用法术，也不意味着应当一有法力就施放？先记下自己的解释，后续课用资源争用实验验证。

## 把问题翻译成接口

下表的接口签名来自历史 `data/seasons/2026-aiyouth/mages-might/api.json`。2027 页面阅读记录同时指出果农有效入口，但不能据此认定所有字段跨版本都已重新实测。

| 要回答的问题 | 入口 | 使用边界 |
| --- | --- | --- |
| 我有哪些果农？ | `hero.findMyCollectors()` | 列表与每个对象的字段分开核对，不随意读取隐藏字段 |
| 我有多少火法力？ | `hero.getTotalMana("fire")` | 查询具体池要传元素；无参历史样本是三池之和，不当作火池 |
| 对面有哪些来袭飞弹？ | `hero.findEnemyMissiles()` | 未看到某类飞弹不等于该类法术不存在 |
| 果农下一次采哪种水果？ | `hero.chooseItem = function (collector) { return "fire"; }` | 是选择回调；完整调度在后续课讲解，不据此保证固定收入 |
| 能否尝试一个法术？ | `hero.canCast(spellName)` | 不把一次 false 解释为某一种唯一原因；冷却等语义按各项证据区分 |
| 发出施法调用？ | `hero.cast(spellName)` | 已发生调用、返回值和实际效果是三件事；不能用返回值当胜负 |

不要用简介里出现过的 `hero.collectors` 替代有效入口：逐字段探测曾发现该属性读取被拦截。也不要添加未验证的隐藏 API。

以下只展示三种读取入口，不是完整策略；不打印结果、不运行对局，不因代码能解析就认定其效果已实测：

```javascript
var ownCollectors = hero.findMyCollectors();
var fireMana = hero.getTotalMana("fire");
var incomingMissiles = hero.findEnemyMissiles();
```

## 三种说法，三种标签

| 说法 | 标签 | 还需要什么 |
| --- | --- | --- |
| 「简介这样写」 | 文档说明 | 指明页面与版本；需要时再实测 |
| 「这一局的这一帧如此」 | 观测证据 | runId、源码身份、帧与错误检查；不外推所有对手 |
| 「多造果农可能更好」 | 策略假设 | 明确生成阻塞与收入成本，设计对照，而不是直接宣布最优 |

已有补测快照在 `data/maps/mages-might/2026-10-08/`：实际页面为 2027 联盟，部分数据明确继承历史，版本等价未证明。`unknown`、估计值和样本不足不是教学的瑕疵，而是练习验证方法的入口。

## 小练习

1. 查询水、土法力应怎样改上面的代码？无参 `getTotalMana()` 能替代吗？
2. 有一个果农消失了。哪些证据能证明它死亡？为什么仅凭列表变化还不能确认死亡原因？
3. 护盾消失时恰好有飞弹落地，能否宣布「护盾到期」？还要看什么？
4. 果农数量更多的一局输了，是否证明「少造果农更好」？怎样让对照只改变一个因素？

教师提示：第 1 题传对应元素，无参合计不能替代单池；第 2 题区分观测缺失、生命、身份及伤害帧；第 3 题区分被打碎与自然到期，未知期限不强行填值；第 4 题控制对手、采集与攻防方案，并保留失败和异常记录。

## 教师验证边界与下一课

需要在官方页面验证示例时，先读 `docs/guides/competition-probing.md`：重进后点击右下角「开始」，只运行不评分，观测从 `world.frames` 读取，不往策略加入 `print`。快速结果用于普通对照，需要分析发生过程时再用回放。

本课不需要复杂规划器、真人高分或全库探测。下一课只做一份能解释的采集与基本攻击示例，再一步步比较扩张、攻防预算与反馈；每次改动回答「为什么改、怎样验证、哪些结论仍不能下」。
